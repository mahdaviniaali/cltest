```text
تعریف → معماری → تصمیم (ADR) → L1 spec → کد + test → doc sync (A4)
```

## Workflow — قبل از هر فاز

### گام ۱ — Alignment (هم‌ترازی)

- [ ] [`تعریف_پروژه.md`](تعریف_پروژه.md) خوانده و scope تأیید شد
- [ ] open questions مربوط به فاز لیست و owner دارند
- [ ] capability target برای فاز در capability_map مشخص است

### گام ۲ — Architecture Session

خروجی هر session **یکی از این‌ها**:

| خروجی | مقصد |
|---|---|
| تصمیم معماری | ADR جدید در `*/decisions/` |
| سؤال باز | `application/spec/open_questions.md` |
| fact جدید | L1 owner file |
| تغییر phase | `product_blueprint.md` |

**قانون session:** در یک session یا **تصمیم** می‌گیریم یا **سؤال** ثبت می‌کنیم — «بعداً» بدون OQ ممنوع.

### گام ۳ — Implementation Gate

merge مجاز فقط وقتی:

```
- [ ] ADR برای why (اگر architectural)
- [ ] L1 owner patch (اگر public API/behavior)
- [ ] test سبز
- [ ] heavy vs light sync (AUTHORITY checklist)
```

## Decision Framework

وقتی بین گزینه‌ها مردد هستیم:

```text
1. آیا Platform/Application boundary را می‌شکند؟ → reject
2. آیا L1 fact بدون کد می‌سازد؟ → reject (aspirational)
3. آیا ADR می‌تواند why را freeze کند؟ → ADR
4. آیا فقط preference است؟ → OQ تا stakeholder input
5. آیا reversible است؟ → working doc OK
6. آیا irreversible است؟ → ADR required before code
```

## Lessons from site-map (منتقل‌شده)

| lesson | action در cltest |
|---|---|
| Fidelity over size | JSON MVP OK؛ schema extensible design |
| Engine behind adapter | HttpClient abstract — future swap بدون App change |
| Host vs Runtime boundary | AI/RAG خارج از crawler |
| Capability ≠ Milestone | capability_map جدا از phase gates |
| No speculation in L1 | knowledge/spec برای draft |
