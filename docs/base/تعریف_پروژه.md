## One-liner

> **Bama.ir New Ads Crawler & Notification System** — سرویسی که آگهی‌های جدید خودرو در Bama.ir را monitor می‌کند، deduplicate می‌کند، با فیلترهای کاربر match می‌کند، و notification ارسال می‌کند.

## Overview

| محور | توضیح |
|---|---|
| **هدف تسک** | ارزیابی طراحی و پیاده‌سازی backend production-oriented |
| **Target site** | [Bama.ir](https://bama.ir) — آگهی‌های خودرو |
| **Trigger** | آگهی **جدید** publish شده — نه re-crawl کل سایت |
| **Consumer** | کاربرانی با search/filter تعریف‌شده |

### مهارت‌های مورد ارزیابی

- User-defined filters

## Functional Requirements

### 2.1 Crawling

کرالر باید **به‌صورت دوره‌ای** Bama.ir را برای آگهی‌های **جدید** بررسی کند.

| requirement | detail |
|---|---|
| Extract | اطلاعات relevant هر آگهی |
| Detect new | آگهی‌هایی که قبلاً دیده نشده‌اند |
| Store | ذخیره آگهی‌های کشف‌شده |
| Dedup | بدون duplicate record |
| Resilience | graceful failure handling |
| Schedule | interval قابل تنظیم |

#### حداقل فیلدهای Advertisement

| Field | required | note |
|---|---|---|
| Advertisement ID / unique identifier | ✅ | اگر Bama stable ID نداشت → assumption معقول |
| URL | ✅ | |
| Title | ✅ | |
| Price | ✅ | |
| Brand | ✅ | |
| Model | ✅ | |
| Year | ✅ | |
| Mileage | ✅ | |
| Location | ✅ | |
| Publication time | ✅ | |
| Crawled time | ✅ | timestamp crawl |
| Other useful fields | optional | هر فیلد مفید دیگر |

#### محدودیت‌های قانونی و ethical

- ✅ respect `robots.txt`
- ✅ respect terms of service
- ✅ respect rate limits
- ✅ applicable legal requirements
- ❌ **ممنوع:** bypass anti-bot، دور زدن access control

### 2.2 User Management & Filters

کاربران باید بتوانند **search criteria** تعریف کنند.

#### نمونه criteria

| Field | Example |
|---|---|
| Brand | Toyota |
| Model | Corolla |
| Minimum Year | 2020 |
| Maximum Price | 3,000,000,000 |
| Maximum Mileage | 100,000 |
| Location | Tehran |

#### عملیات مورد نیاز

| Operation | required |
|---|---|
| Create search/filter | ✅ |
| Update search/filter | ✅ |
| Delete search/filter | ✅ |
| Enable / disable search/filter | ✅ |
| View configured searches | ✅ |
| Multiple searches per user | ✅ |

#### مثال

```text
User A
  Search #1: Toyota Corolla, Year >= 2020, Price <= 3B
  Search #2: BMW 320,       Year >= 2018, Price <= 5B
```

### 2.3 Matching Engine

وقتی آگهی **جدید** کشف شد → تعیین کدام user searches match می‌کنند.

```text
New Ad: Toyota Corolla · 2022 · 80,000 km · 2.8B · Tehran
                    │
                    v
            Matching Engine
                    │
        ┌───────────┼───────────┐
        v           v           v
  User A / S#1 ✓  User B / S#4 ✓  User C / S#7 ✗
```

| requirement | detail |
|---|---|
| Match on new ad | فقط آگهی‌های تازه کشف‌شده |
| No repeat notify | همان ad + همان user + همان search → **یک‌بار** notify |
| Extensible criteria | فیلترها data-driven باشند (نه hard-coded per brand) |

---

### 2.4 Notifications

وقتی match رخ داد → notification به کاربر.

| requirement | detail |
|---|---|
| Minimum channels | **≥ 1** (Email / Telegram / Webhook / Push / …) |
| Content | اطلاعات مفید آگهی + لینک |
| Extensibility | channel جدید **بدون تغییر اساسی** crawler یا matching logic |

#### نمونه محتوای notification

```text
New car advertisement found

Toyota Corolla 2022
Price: 2.8B
Mileage: 80,000 km
Location: Tehran

https://...
```

## Logical Subsystems (مرز مسئولیت)

| Subsystem | Job | وابستگی |
|---|---|---|
| **Crawler** | fetch + extract + normalize + dedup + persist ads | Bama.ir, scheduler |
| **Ad Store** | نگهداری آگهی‌ها + dedup key | persistence |
| **User/Search API** | CRUD searches + enable/disable | auth (TBD) |
| **Matching Engine** | new ad → matched searches | ad store, search store |
| **Notification** | deliver + idempotency (no repeat) | matching result |
| **Scheduler** | periodic crawl trigger | configurable interval |

> **تفکیک Platform/Application** و stack تکنولوژی → در رویکرد پروژه (هنوز open).

### دسته اول — خزش (Crawling)

### سناریوی End-to-End

```text
1. کاربر «علی» در سیستم شناسایی/ثبت‌نام می‌شود (auth: TBD).

2. علی یک فیلتر می‌سازد:
   تویوتا کمری · سال ≥ ۱۴۰۰ · قیمت ≤ ۳ میلیارد.

3. Scheduler هر ۵ دقیقه (interval قابل تنظیم) لیست/صفحات Bama.ir را برای آگهی جدید می‌خواند.

4. امروز آگهی جدید «تویوتا کمری ۱۴۰۲ — ۲.۹ میلیارد» منتشر می‌شود.

5. Crawler آگهی را می‌بیند؛ در persistence نبود → extract + normalize + store.

6. Matching Engine (sync یا async) آگهی را با همه فیلترهای فعال مقایسه می‌کند.

7. فیلتر علی match می‌شود.

8. سیستم رکورد notification/idempotency ثبت می‌کند
   تا همان (ad, search) دوباره notify نشود.

9. Notification به علی ارسال می‌شود:
   «آگهی جدید: تویوتا کمری ۱۴۰۲ — قیمت ۲.۹ میلیارد — [لینک]».
```
